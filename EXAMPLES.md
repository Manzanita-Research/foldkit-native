# Examples

A gallery of FoldKit apps drawn natively by GPUI. Most are FoldKit's own
[example apps](https://foldkit.dev/example-apps), ported with their code and
their tests; one is a GPUI showcase written here. Each example says what it
shows from **FoldKit** (the app side) and what it shows from **GPUI** (the
drawing side).

```sh
bun run gallery              # a window listing every example; click one to open it
bun run gallery --list       # the same list in the terminal
bun run example weather      # open one example directly
```

Every example runs on **FoldKit on gpuix** ([packages/foldkit-gpuix](packages/foldkit-gpuix)),
with no DOM engine. The DOM mirror (happy-dom → GPUI, `src/`) is kept as a
comparator: `FOLDKIT_NATIVE_RENDERER=mirror bun run example weather` (or
`bun run gallery`) opens one on it, and CI runs every example's tests on both.
Layer bar and Native UI are built on `@foldkit-native/ui`, so they run on the
adapter only (`meta.renderer`).

## The list

| Example | Shows from FoldKit | Shows from GPUI | Source |
|---|---|---|---|
| **Weather** | An HTTP Command (Open-Meteo, no key), loading, failure and success states with `AsyncData`, a form built from `@foldkit/ui` Input and Button | A native text input, a gradient background, a rounded card with a soft shadow | FoldKit `examples/weather` |
| **Kanban** | Drag and drop between columns, keyboard reordering, fractional indexing, screen reader announcements | Pointer drags with live drop targets, layered rounded cards with shadows | FoldKit `examples/kanban` |
| **Snake** | A game loop and the keyboard as Subscriptions, pure game logic in `update` | Redrawing a whole grid every tick at high refresh rates | FoldKit `examples/snake` |
| **Form** | Field validation, error states, an async submit Command | Text inputs, focus rings, typing latency | FoldKit `examples/form` |
| **Pixel Art** | Undo, redo and time-travel history, `@foldkit/ui` Dialog, RadioGroup, Switch and Listbox, saved state passed in as Flags | Thousands of live cells repainting under a dragging pointer | FoldKit `examples/pixel-art` |
| **Shopping Cart** | Routing between pages, Submodels for each page, a cart that survives navigation | Page changes, scrolling product lists, hover states | FoldKit `examples/shopping-cart` |
| **Big List** | A live filter and keyboard selection over 10,000 rows, theme tokens switched at runtime | Smooth scrolling of a long list, theming, shadows and rounded layers | New, written here |
| **Layer bar** | A clock Subscription, buttons from `@foldkit-native/ui`, a theme switched at runtime | A Wayland layer-shell surface along the top of the screen, with an exclusive zone (a small window elsewhere), from foldkit-gpuix's `bar()` | New, written here |

The existing **Counter** and **Themes** demos stay in the gallery too.

## Not yet

What's left, on the adapter (the mirror has more gaps; the examples' tests say
which renderer passes what):

- **Canvas Art** and **Generative Art** draw with FoldKit's `Canvas.view`
  (a `<canvas>` 2D context). gpuix has a canvas element, but neither renderer
  maps `<canvas>` to it yet: a `<canvas>`'s `getContext()` is `null`.
- **Map**, **Charting** and **Web Components** mount third-party browser
  libraries (MapLibre, ECharts, custom elements) that need a real browser
  engine.
- **UI Showcase** covers every `@foldkit/ui` component. Not ported yet. The
  pieces it needs now work on the adapter: layout read-back, and anchored
  panels (Listbox, Menu, Popover) placed by Floating UI, as Pixel Art's theme
  list shows.
- **Pixel Art**'s Export PNG draws on a 2D `<canvas>`, so it ends in the app's
  "Export Failed" dialog (see Canvas, above). The inline SVG icons don't draw.
- **Shopping Cart**: nothing in GPUI goes back or forward by itself. The
  in-memory `history` and `location` are all its router needs (`back()` and
  `forward()` fire `popstate`), but gpuix 0.10 reports only the left, middle
  and right mouse buttons, so the mouse's back button can't reach the app.
- **Tailwind's `space-y-*`** is lost (Shopping Cart's cart rows touch): it's a
  child combinator with `:not(:last-child)`, and the adapter's sheet reads one
  element at a time (the mirror's happy-dom never matches it either).

## What every example has

Each example lives in `examples/<name>/`:

| File | What it is |
|---|---|
| `main.ts` and friends | The app. For a FoldKit port, FoldKit's code, unchanged apart from a credit header. |
| `app.ts` | `meta` (what the gallery shows) and `start(container)`: FoldKit's `entry.ts`, with the container passed in. |
| `styles.css` | The app's CSS as written (FoldKit's examples use Tailwind 4). |
| `styles.native.css` | Generated by `bun run css`: the same CSS, lowered to what the adapter's sheet (and happy-dom, for the mirror) read. Checked in; CI fails if it's stale. |
| `story.test.ts` | **Story tests**, FoldKit's own kind: Messages through `update`, assertions on the Model and the Commands. No view, no DOM. For a port, FoldKit's file, unchanged. |
| `scene.test.ts` | **Scene tests**, FoldKit's own kind: the rendered view, driven by clicks and typing, with assertions on what's on screen. For a port, FoldKit's file, unchanged. |
| `native.test.ts` | **Native tests**: the real app on FoldKit on gpuix, driven by GPUI's input (`FOLDKIT_NATIVE_RENDERER=mirror` runs them on the mirror). Headless anywhere (GPUI's tree); on macOS also drawn by Metal offscreen, with screenshots. |
| `demo.ts` | The scripted walk-through `bun run record <name>` films (as `<name>-adapter.mp4`; the mirror's clips, recorded before, are `<name>.mp4`). |

How the tests work, where each kind runs, and where screenshots and clips go:
[TESTING.md](TESTING.md). `examples/weather` is the reference: copy its shape.

## Porting a FoldKit example

1. Copy `examples/<name>/src/*` from FoldKit (at the commit below) into
   `examples/<name>/`, and add the credit header to each file. Leave
   FoldKit's `entry.ts`, `vitest-setup.ts`, `vite.config.ts` and
   `index.html` behind.
2. Write `app.ts`: `meta`, and `start` doing what FoldKit's `entry.ts` did,
   with `container` passed in and no `devTools`.
3. `bun run css`, then `bun test ./examples/<name>`: FoldKit's story and scene
   tests should pass unchanged. If one can't, say why in the PR.
4. Write `native.test.ts` with `examples/support/harness.ts`: draw it, drive
   its main interaction with GPUI's input, check GPUI's tree, and on Metal
   take a screenshot of each step. Stub any network. It runs on the adapter;
   check it on the mirror too (`FOLDKIT_NATIVE_RENDERER=mirror`), and mark a
   test that only one renderer passes with `test.skipIf` and the reason.
5. Write `demo.ts`, and run `bun run example <name>` to look at it.

Anything FoldKit Native can't do yet is a finding: write a failing (skipped)
test or a note in the PR, and add it to "Not yet" above.
